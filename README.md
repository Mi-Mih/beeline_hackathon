# 🚐 Планировщик выездов технических специалистов «Смена»

Сервис составляет маршруты выездных бригад по заявкам и умеет пересчитывать
оставшуюся часть плана во время смены. Он учитывает окна обслуживания, рабочие
смены, навыки, транспорт, оборудование, приоритет заявки и ручное закрепление
специалиста.

Проект включает HTTP API, веб-интерфейс диспетчера, математическое ядро на
OR-Tools и интеграцию с локальным OSRM для расчёта дорожных расстояний и времени
в пути по Москве.

## ✨ Возможности

- предсменное планирование и перепланирование в течение дня;
- открытые маршруты: возвращение в офис после последней заявки не добавляется;
- основной решатель open VRPTW на OR-Tools Routing;
- резервный алгоритм greedy + local search, если основной решатель недоступен
  или не нашёл допустимого решения;
- объяснимые причины для неназначенных заявок;
- стабильные JSON-контракты входа и результата;
- дорожная матрица и геометрия маршрутов через локальный OSRM;
- импорт фактических поездок и экспериментальная персональная калибровка времени;
- управление версиями дорожного графа и его обновлением;
- статический интерфейс диспетчера без отдельной frontend-сборки.

## 🚀 Быстрый старт

Требуется Python 3.12 или новее.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
ROUTING_MATRIX_MODE=input python -m backend --host 127.0.0.1 --port 4173
```

После запуска интерфейс доступен по адресу <http://127.0.0.1:4173>. Режим
`input` предназначен для локальной демонстрации: матрица поездок берётся из
входного JSON. Для штатного режима с дорожной матрицей используется локальный
Routing Gateway и OSRM.

### Демо на 30 бригад

В проект включён синтетический сценарий `examples/synthetic-ui-30-300.json`:
30 бригад, 300 заявок и готовая матрица поездок. Для расчёта локальный OSRM не
нужен.

Linux/macOS:

```bash
source .venv/bin/activate
ROUTING_MATRIX_MODE=input python -m backend --host 127.0.0.1 --port 4173
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
$env:ROUTING_MATRIX_MODE = "input"
python -m backend --host 127.0.0.1 --port 4173
```

Открыть <http://127.0.0.1:4173> и нажать **«Демо: 30 бригад»**. Расчёт
выполняется локально. При выборе «Все бригады» дорожная геометрия запрашивается
последовательно у публичного OSRM; её первое отображение может занять от 30
секунд. Если внешний сервис недоступен, план остаётся доступен, а карта
показывает схематические линии.

Подробное описание данных и интерфейса:
[`docs/ui-large-demo.md`](docs/ui-large-demo.md).

Проверка математического ядра без HTTP:

```bash
python -m backend.math_core examples/sample-input.json > plan.json
```

Подробные инструкции для Python и Docker, переменные окружения и диагностика:
[`RUN.md`](RUN.md).

## 🔌 Контракты и точки входа

- `contracts/plan-input.schema.json` — входной снимок заявок, специалистов,
  локаций и матрицы поездок;
- `contracts/plan-output.schema.json` — маршруты, метрики, неназначенные заявки
  и диагностика;
- `POST /api/plan` — основной HTTP-вызов планировщика;
- `backend.math_core.Planner.plan(problem)` — граница математического ядра;
- `python -m backend.math_core <input.json>` или `beeline-planner` — CLI;
- `python -m backend` или `beeline-web` — HTTP-сервис.

## ⚠️ Ограничения текущей версии

- в рабочем API нет аутентификации и постоянного хранилища заявок или планов;
  клиент передаёт полный снимок на каждый расчёт;
- штатный режим требует координаты всех точек и готовый локальный OSRM-граф;
- OSRM не учитывает пробки в реальном времени;
- состояние Map Manager и история поездок хранятся в SQLite и рассчитаны на
  один узел;
- изменяющие методы `/api/map/*` и Docker socket нельзя публиковать в
  недоверенную сеть без внешнего контроля доступа;
- синтетические примеры и публичная геометрия демо не являются production-
  источником дорожных данных.
