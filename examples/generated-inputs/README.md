# Входные данные для прогонов

В каталоге находятся девять воспроизводимых входов `plan-input 1.0`: три
размера для каждой зоны из `data/* Синтетические данные.csv`.

| Сценарий | Заявок | Инженеров |
|---|---:|---:|
| `small` | 12 | 4 |
| `medium` | 32 | 8 |
| `full` | все заявки зоны | все бригады из контрольного CSV |

Выборки вложены: все заявки `small` входят в `medium`, а `medium` — в `full`.
Каждый доступный тип заявки сначала представлен хотя бы одной строкой, остальные
строки упорядочены стабильным хешем.

## Что взято из исходных файлов

- идентификатор, тип, окно, район и адрес заявки — из синтетических CSV;
- имена инженеров — уникальные непустые значения `Бригада` из контрольных CSV;
- адрес офиса — из служебной строки в конце синтетического CSV;
- длительности работ — из `config/work-normatives.json`.

## Тестовые допущения

В источниках нет координат, дорожной матрицы, смен, навыков, транспорта и
оснащения инженеров. Поэтому эти поля предназначены только для прогонов:

- все инженеры стартуют из офиса за час до самого раннего окна и заканчивают
  смену через два часа после самого позднего окна;
- все инженеры имеют четыре навыка и автомобиль, требования к транспорту и
  оборудованию у заявок отключены;
- точки строятся детерминированно в синтетической плоскости: один район образует
  кластер, адрес задаёт небольшой сдвиг внутри него;
- расстояние равно евклидову расстоянию с дорожным коэффициентом `1.25`, время
  рассчитано для средней скорости `25 км/ч` плюс три минуты;
- матрица полная и симметричная. Она не является реальной дорожной матрицей.

## Пересоздание и запуск

```bash
python scripts/generate_run_inputs.py
python -m backend.math_core examples/generated-inputs/восток-small.json
```

Список файлов и их размеры записан в `manifest.json`.
